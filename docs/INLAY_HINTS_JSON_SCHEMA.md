# Baa Inlay Hints JSON Schema

> **Version:** draft-0.1 | **Applies to:** Baa v0.7.x+

يصدر باء تلميحات أسماء المعاملات من ربط الاستدعاءات الدلالي. لا يستنتج
`Baa-LSP` أو قلم اسماً من النص أو من تشابه أسماء الدوال. الواجهة:

```text
baa --inlay-hints=json --source-stdin=<المسار_المنطقي>
```

ويقرأ المصرف نص UTF-8 غير المحفوظ من الدخل القياسي. مثال مختصر:

```json
{
  "schema_version": "inlay-hints-json-v1",
  "compiler_version": "0.6.0",
  "file": "رئيسي.baa",
  "position_encoding": "utf-8-bytes",
  "complete": true,
  "hints": [
    {
      "position_byte": 120,
      "kind": "parameter",
      "label": "قيمة:",
      "parameter": "قيمة",
      "padding_right": true
    }
  ]
}
```

## القواعد

- `position_byte` موضع الإدراج قبل أول بايت في تعبير الوسيط ضمن الملف المنطقي.
- `label` نص العرض العربي المملوك لباء، و`parameter` اسم المعامل المربوط.
- لا يصدر باء تلميحاً إذا كان الوسيط مرجع متغير يطابق اسم المعامل تماماً؛ هذا
  الاستدعاء واضح ولا يحتاج ضجيجاً بصرياً.
- لا تصدر تلميحات للمعاملات المتغيرة التي لا تملك أسماء ثابتة في التصريح.
- `complete: false` يعني أن المحلل استعاد شجرة جزئية من خطأ نحوي أو دلالي؛ كل
  تلميح موجود يظل مبنياً على تصريح معروف، لكن القائمة ليست وعداً باكتمال الملف.
- الترتيب حتمي وتصاعدي حسب `position_byte` ثم اسم المعامل. الحد الأقصى 4096
  تلميحاً؛ إذا تجاوز الملف هذا الحد تصبح `complete` كاذبة بدلاً من إخفاء القطع.
- يتحقق المستهلك من حدود البايت ومن أن الموضع يقع على حد UTF-8 قبل تحويله إلى
  UTF-16. ويجب أن يهمل النتيجة إذا تغير إصدار المستند أثناء الطلب.
